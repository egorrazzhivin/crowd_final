# Детекция бабочек и мотыльков

Локальная разметка фотографий тремя моделями: GroundingDINO, OWLv2 и Qwen3-VL.
Нужно найти всех взрослых бабочек и мотыльков отдельными рамками, включая видимые
части крыльев, тела, усиков и ног. Гусеницы, куколки и другие насекомые не относятся
к целевому классу. Полное условие — `final-project-2026_updated.pdf`.

## Что уже сделано

- На каждом из двух датасетов по 400 фото запущены все три модели.
- У DINO и OWLv2 порог запуска `0.0`, NMS выключен: сохранены все выданные кандидаты
  и их scores, чтобы менять порог без повторного инференса.
- У Qwen нет оценки уверенности рамок. Его результат — готовый список рамок.
- Две ошибки Qwen на нашем датасете исправлены отдельным повторным прогоном.
  История, настройки повторного прогона и исходные ответы сохранены рядом с результатом.
- Метрики посчитаны на 358 фото нашего gold. Ещё 42 фото не размечены.
- Подбор порогов и NMS пока не выполнен. Готового скрипта экспорта результата
  с выбранными порогами для контеста пока нет.

## Структура

```text
final_project/
  README.md
  final-project-2026_updated.pdf
  requirements.txt
  label.py                 # загрузка фото, инференс, проверка ответов
  visualize.py             # рамки на одном фото
  evaluate.py              # метрики на ours_gold
  compress_results.py      # сжатие больших JSONL с проверкой SHA-256
  prompts/
    detector.txt           # запросы DINO/OWL, по одному на строку
    qwen.txt               # инструкция Qwen; формат JSON добавляет label.py
  data/
    dataset_ours.jsonl
    dataset_contest.jsonl
    submission-template.jsonl
    gold/
      ours_gold.jsonl      # ручная разметка, пока 358 фото
      contest_gold.jsonl   # только локально, запрещён к публикации
    predictions/
      dataset_<ours|contest>_<model>_threshold-<value>[_nms-off]/
        predictions.jsonl[.gz]
        log.jsonl[.gz]
        run.json
      compression_manifest.json
    experiments/           # ранние тестовые прогоны, выборки и сводки
    logs/                  # исторические логи очереди запусков и переносов
    metrics/
      ours_baseline.json   # агрегированные и пофотографийные метрики
  .image_cache/            # скачанные фотографии, не в Git
  .model_cache/            # веса Hugging Face, не в Git
  .venv/                   # окружение, не в Git
```

Код, исходные списки фотографий, наш gold, результаты моделей, метрики и логи
предназначены для Git. Картинки, кеши, веса, окружение, временные файлы и
`contest_gold*` исключены через `.gitignore`. Не добавляйте конкурсный gold через
`git add -f`, не переименовывайте его для публикации и не включайте в архивы.
`evaluate.py` читает только `ours_gold.jsonl`.

Логи старых запусков и `run.json` могут содержать прежние абсолютные пути.
Это история запуска; текущие скрипты вычисляют пути относительно своего каталога.

## Установка

Команды ниже выполняются из `final_project/`. Использовался Python 3.12 на macOS
с Apple Silicon; модели запускались на MPS.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Для расчёта метрик по готовым файлам GPU и веса моделей не нужны. При первом новом
инференсе веса скачиваются с Hugging Face, фотографии — по URL датасета.

## Форматы и движение данных

Исходный датасет — JSONL, одна фотография на строку:

```json
{"photo_id": 123, "photo_url": "https://example.org/photo.jpg"}
```

`label.py` скачивает фото в общий кеш, применяет EXIF-поворот, переводит в RGB
и уменьшает с сохранением пропорций до максимальной стороны 1280 пикселей.
Модель получает изображение и промпт; ручная разметка ей не передаётся.

Результат `predictions.jsonl` содержит `photo_id`, `photo_url`, `boxes`, `error`.
Каждая рамка имеет вид:

```json
{"left": 0.1, "top": 0.2, "width": 0.3, "height": 0.4}
```

Координаты нормализованы относительно изображения. `boxes: []` — успешный ответ
«объектов нет». `boxes: null` и непустой `error` — ошибка обработки, а не негативный
пример. В gold поле `photo_url` не требуется; сопоставление идёт по `photo_id`.

У детекторов `log.jsonl` содержит исходные `xyxy` в пикселях обработанного фото,
соответствующие `scores` и `image_size: [width, height]`. Scores находятся в том же
порядке, что и рамки. Порог применяется как `score > threshold`, затем координаты
обрезаются по границам изображения и нормализуются. Рамки целиком вне изображения
отбрасываются. Для OWLv2 учтён padding до квадрата.

У Qwen в логе лежит исходный текст ответа. Его координаты `bbox_2d` имеют масштаб
0–1000 и преобразуются в тот же итоговый формат. Текущий код проверяет JSON
и координаты; при ошибке выполняет до двух повторов с sampling (`temperature=0.2`,
`top_p=0.9`), сохраняет неудачные ответы в `failed_json_attempts`.
Это не принудительный structured output: после трёх провалов сохраняется ошибка.
Исторические полные прогоны сделаны до добавления этой автоматической логики.

`run.json` фиксирует промпт, настройки, ревизию весов, версии библиотек,
устройство, seed и SHA-256 входного датасета.

## Переиспользование готовых результатов

Большие `predictions.jsonl` и `log.jsonl` сохранены как `.jsonl.gz`. Сжатие
без потерь: перед удалением несжатого оригинала проверяется SHA-256 распакованных
байтов. Размеры и контрольные суммы записаны в `compression_manifest.json`.

`evaluate.py` и `visualize.py` читают gzip напрямую. Если указанный `.jsonl`
отсутствует, автоматически ищется `.jsonl.gz`. Модели повторно запускать не нужно.
Вручную распаковать архив, сохранив его, можно так:

```bash
gunzip -k data/predictions/dataset_ours_owlv2_threshold-0.0/log.jsonl.gz
```

После новых больших прогонов сжатие запускается отдельно:

```bash
python compress_results.py
```

## Метрики

```bash
python evaluate.py --output data/metrics/ours_recheck.json
python evaluate.py --dino-threshold 0.4 --owl-threshold 0.3 --output data/metrics/ours_threshold_test.json
```

Скрипт читает готовые полные прогоны, фильтрует кандидатов DINO/OWL по score
и оценивает только фотографии из нашего gold. Отсутствующие в gold фотографии
исключаются, а не считаются негативами. Ошибка предсказания не подменяется пустым
списком. Существующий файл отчёта не перезаписывается.

Сопоставление рамок — один к одному, максимальное количество совпадений при
`IoU >= 0.5` или `IoU >= 0.75`; при равном количестве максимизируется суммарный IoU.
Precision, recall и F1 считаются по суммарным TP/FP/FN, а не усреднением по фото.
Отдельно считаются ложные срабатывания на негативных фотографиях.

Текущая база: 358 фото, 302 объекта, 97 негативных фото, NMS выключен:

| Модель | Порог score | Precision @0.5 | Recall @0.5 | F1 @0.5 | F1 @0.75 |
|---|---:|---:|---:|---:|---:|
| GroundingDINO | 0.25 | 0.2221 | 0.8907 | 0.3556 | 0.3384 |
| OWLv2 | 0.1 | 0.1856 | 0.9470 | 0.3104 | 0.2008 |
| Qwen | нет | 0.9682 | 0.9073 | 0.9368 | 0.8103 |

Низкая precision детекторов здесь включает штраф за дублирующиеся рамки.
Это исходное сравнение без подбора порогов и NMS.

## Просмотр рамок

```bash
python visualize.py data/predictions/dataset_ours_qwen_threshold-none --photo-id 630575872 --output /tmp/qwen.png
```

Можно передать каталог прогона либо конкретный `.jsonl`/`.jsonl.gz`.
Без `--photo-id` показывается первая запись. Если в разметке нет URL,
передайте `--dataset data/dataset_ours.jsonl`. Изображение берётся из кеша
или скачивается; готовый PNG не перезаписывается.

## Новый инференс

Готовые результаты уже включены. Эти команды нужны только для нового запуска:

```bash
python label.py dataset_ours.jsonl detector.txt --model grounding-dino --threshold 0 --device mps
python label.py dataset_ours.jsonl detector.txt --model owlv2 --threshold 0 --device mps
python label.py dataset_ours.jsonl qwen.txt --model qwen --device mps
```

Модели: `IDEA-Research/grounding-dino-tiny`, `google/owlv2-base-patch16`,
`Qwen/Qwen3-VL-2B-Instruct`. `--device auto` выбирает CUDA, затем MPS, затем CPU.
Для воспроизведения весов передайте `--revision` из соответствующего `run.json`.
`HF_HUB_OFFLINE=1` отключает сетевую загрузку весов при заполненном кеше;
загрузка фотографий этим не отключается.

NMS поддерживается при инференсе только у DINO и включается исключительно флагом
`--nms-iou`, например `--nms-iou 0.5`. По умолчанию NMS выключен. У Qwen нет
`--threshold`; `--max-new-tokens` применяется только к нему, по умолчанию 2048.
`--limit N` позволяет сделать пилот, но имя выходного каталога от этого не меняется.

Скрипт отказывается перезаписывать существующий прогон, включая сжатые файлы.
Перед намеренным повторным запуском перенесите старый каталог в отдельное место
или используйте другую входную выборку с другим именем. Автоматического resume нет.
Модели запускайте последовательно, длинные прогоны — в фоне с логом в файл.

## Что делать следующему участнику

1. Дополнить `ours_gold.jsonl` оставшимися 42 фото и пересчитать базовые метрики.
2. На нашем gold подобрать пороги и NMS по сохранённым scores и рамкам.
   `evaluate.py` пока умеет менять только пороги, без NMS.
3. Зафиксировать выбранные параметры и сравнить модели при одинаковом наборе фото.
   Если параметры выбирались на этом же gold, указать, что оценка не независимая.
4. Применить выбранную обработку к готовому конкурсному прогону. Конкурсный gold
   не использовать для выбора параметров, промптов или модели.
5. Подготовить отдельный файл сдачи: 400 уникальных ID, нормализованные рамки,
   отсутствие ошибок; проверить формат и лимит размера из условия.
   Детекторные файлы с нулевым порогом — наборы кандидатов, не готовая сдача.

Компонент моделей не заменяет обязательные части проекта с ручной разметкой,
проверкой разметки и итоговым анализом из условия.
